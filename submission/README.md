# Комплект сдачи и будущая публикация

## Что передать проверяющему

В `submission/artifacts/` подготовлены отдельные файлы для сдачи. Они исключены из Git.

| Файл | Назначение |
|---|---|
| `dashboard.html` | Дашборд практики № 2 в одном HTML |
| `orenburg_pipeline.executed.ipynb` | Ноутбук практики № 2 с выводами контрольного прогона |
| `orenburg-data.zip` | Точный PBF BBBike, выгрузка, GraphML и обязательный кэш для запуска после клонирования |

Видеодемонстрацию прикрепите как отдельный материал или добавьте ссылку в форму сдачи. Видео и архив данных не включаются в историю Git. Выгрузка в архиве содержит те же аналитические файлы. В копии манифеста машинные пути заменены относительными, контрольные суммы данных сохранены. Исходный PBF имеет SHA-256 `330f7da852f84ee26bf8e48c71c80c9802f401896a30e50b1bbec70cef0dd85f`.

Из существующих локальных данных HTML и архив пересобираются командой:

```powershell
& .venv/Scripts/python.exe -B submission/package.py
```

В чистом клоне для воспроизведения разверните архив в корень проекта. Свежая выгрузка BBBike может отличаться по содержанию. Версии зависимостей и инструкции лежат в [плане исследования](../ORENBURG_RESEARCH.md).

## Публикация после отдельного согласования

1. В аккаунте **annkamyanenko** создайте отдельный пустой репозиторий, например `orenburg-spatial-analytics`. Выберите видимость по требованиям сдачи. На этапе создания оставьте репозиторий без автоматически добавляемых README, лицензии и `.gitignore`.
2. Проверьте вкладку Actions нового репозитория. История учебного шаблона включает workflow документации, который может сработать при отправке ветки `main`. Если автоматическая публикация пока не нужна, остановите Actions в настройках нового репозитория перед отправкой.
3. Добавьте новый адрес под отдельным именем. Проверьте владельца, имя и push-адрес. `origin` указывает на исходный учебный шаблон и не используется для отправки сдачи.

```powershell
git remote add submission https://github.com/annkamyanenko/orenburg-spatial-analytics.git
git remote get-url --push submission
git status --short --branch
git log -2 --oneline
```

4. Только после отдельного разрешения выполните `git push submission main`. Для сайта GitHub Pages позже можно опубликовать статические файлы из `dashboard/` отдельным источником Pages. Для сценарного приложения преподаватель запускает локальный сервер после распаковки архива данных.
