# Сценарное моделирование рекреационной обеспеченности Оренбурга

## Запуск

Из корня проекта выполните в PowerShell:

```powershell
& .venv/Scripts/python.exe -B recreation-placement/server.py
```

Откройте [http://127.0.0.1:8033/](http://127.0.0.1:8033/). Для другого порта добавьте `--port 8034`. Остановить сервер можно через Ctrl+C.

Для сценария **А** выберите квартал и добавьте объект по умолчанию на 6000 м². Для **Б** переключите вариант и добавьте два объекта по 3000 м². Площадь каждого объекта редактируется. Справа можно включить пешеходные связи, водно-зелёный каркас, существующие объекты и барьеры. Впишите краткое обоснование через эти слои. Для **В** укажите площадь одного объекта, режим доступа и нажмите «Проверить все кварталы». Таблица покажет все варианты, в том числе кварталы вне привязки и ошибки расчёта. Строку рассчитанного варианта можно открыть на карте.

Результат доступен в трёх режимах карты. «Сохранить сценарий» добавляет его в сравнительную таблицу и сохраняет в браузере. «Сбросить» восстанавливает исходное состояние и сохраняет таблицу ранее сохранённых сценариев. CSV текущего расчёта содержит все кварталы. Рейтинг выгружается отдельной кнопкой.

## Источники и расчёт

- Исходные данные читаются из `data/orenburg/results/8d64d1206ffa9bd94e07cad3` и кэша практики № 2. Leaflet, цветовая схема, данные для карты и подложки переиспользуются из `dashboard/`. Сетевые связи и завершённые рейтинги сохраняются в `recreation-placement/.cache/`. Геоданные не скачиваются заново. Интернет используется браузером для Montserrat и спутниковой подложки NASA, если она выбрана.
- Официальный генплан утверждён постановлением № 454-пп от 21.05.2024. Найдена ссылка на карту функциональных зон в приложении № 11 и доступная растровая копия. Готовый открытый вектор не подтверждён. GeoJSON с полигонами функциональных зон в WGS 84 можно загрузить через панель слоёв или поместить в `recreation-placement/functional-zones.geojson`. Для подсказок используется поле `zone_name` или `name`. Слой применяется для ручного обоснования, фактическое землепользование OSM его не заменяет. [Постановление](https://base.garant.ru/409071590/) · [Растровые карты](https://gen-plans.ru/56/orenburg)
- Спрос — калиброванное население × 11 м²/чел. Суммарный дефицит вычисляется на одинаковом наборе привязанных кварталов для каждого сравнения. Непривязанные кварталы показаны как пропуски. Значения для двух режимов имеют разный охват и напрямую несопоставимы.
- Для условного входа выбирается узел пешеходного графа внутри квартала или в пределах 15 м от него, ближайший к репрезентативной точке квартала. Тот же вход привязывается к автомобильной сети в пределах 100 м. Маршруты строятся по направленному графу и учитывают исходные пороги 1000 м и 10 минут. В пешем режиме учитываются расстояния привязки из практики № 2. Вход и новый объект требуют проверки на местности. Площадь объекта задаётся как ресурс, его фактический контур не моделируется.
- Разрежённая модель сохраняет рёбра, ограничения и целевую функцию BlocksNet `спрос × вместимость / (стоимость пути + 1)`. Матрица ограничений — матрица инцидентности двудольного графа с целочисленными запасами. Поэтому вершины многогранника целочисленны, и симплекс HiGHS решает ту же задачу без плотной матрицы и целочисленного перебора. Целочисленность результата и балансы проверяются после решения. Цель и суммарное распределение сверены с BlocksNet на базовых и контрольных сценариях.
- Статический GitHub Pages может показать клиентские файлы, но для сценарных вычислений нужен локальный Python API. Публикация не выполнялась.

## Проверка

```powershell
& .venv/Scripts/python.exe -B recreation-placement/verify.py
```

Проверены идентификаторы и контрольная сумма матрицы, воспроизведение базового распределения по всем кварталам, соответствие прямого и обратного поиска маршрутов на контрольной выборке, допустимость площади, баланс, независимость сценариев, полнота перебора и совпадение ручного результата с рейтингом. В Chrome отдельно проверены выбор квартала, сохранение и возврат сценария, режимы карты, сравнительная таблица, сброс и экспорт CSV.

Квартал 314 в А использован как проверочный пример. Его соответствие генплану не подтверждено. Для примера Б выбраны два приречных квартала с зелёными и рекреационными контурами. Этот выбор иллюстрирует проверку сети, а не подтверждает непрерывность зелёного коридора или пригодность участка. Квартал 0 стоит первым среди равноценных лучших по возрастанию ID. Первый перебор 6000 м² занял около 20 секунд пешком и 6 минут 20 секунд для автомобиля. Повторный запуск при тех же входах читает сохранённый рейтинг.
